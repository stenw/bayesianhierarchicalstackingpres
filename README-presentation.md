# Bayesian hierarchical stacking presentation

Open `bayesian-hierarchical-stacking.html` for the finished deck, or edit `bayesian-hierarchical-stacking.qmd`. Keep `assets/`, `Bayesianhierarchicalstacking_Page_01.jpg`, `_extensions/`, `deck-tweaks.css`, and `bayesian-hierarchical-stacking_files/` beside the HTML file. The original `bayesian-hierarchical-stacking-alt.qmd` remains as the design reference.

The content slides use the layouts from the alt deck. The title slide uses the template's **General** photo and title layout, without the alt deck's article-page image override. The deck uses version 2.4.0 of the supplied `emctemplatereveal` extension, with the unreleased section-line, key-term, citation-line, and closing-image additions. The extension's CSS and images were not changed. `deck-tweaks.css` gives paired boxes equal height on slides 14, 17, and 22; adds a gradual blur and pale fade to the Section 3 opening image and a gentler lower-image blur to the closing slide; adds spacing below two-column boxes; and sizes the forward-validation equations.

The revision expands the paper's Sections 2 and 3 across separate slides. Section 2 covers the leave-one-out mixture score, its posterior interpretation, discrete hierarchical priors, posterior prediction, continuous inputs, and time-ordered prediction. Section 3 opens with a section slide, then covers the Bernoulli example, the two winning-region definitions, the separation conditions, Theorems 1–4, and the assumptions behind the covariate-shift argument. After the examples, two slides marked "Beyond the paper" discuss a gap: the paper covers cell- or subject-specific weights, one-step-ahead scoring of units observed from the start, and briefly leave-one-cell-out densities for new cells (§6.1), but not predictions for a new individual observed only up to a landmark time. Hierarchical pooling across cells and forward scoring for time-ordered data do not themselves establish theoretical guarantees for dependent patient histories and censored landmark outcomes. The second slide outlines what such an extension would need and is labelled as a proposal, not a result of the paper. Work published after the paper is summarized in one table; the discussion of each study is in its speaker notes. Speaker notes give the paper's definitions, equations, limitations, and section references. The deck has 27 slides, including the title, and notes on all 26 other slides.

Every content slide names its section in a short line above the title (`kicker="§3.2 …"`); each subsection of Sections 1–3 has at least one slide. Key terms are marked with `.emc-term`, and their color shows their kind:

| Color | Kind of term | Examples |
| --- | --- | --- |
| Teal (theme accent) | Pooling methods | complete pooling, no pooling, partial pooling |
| Medium blue | Estimation quantities | leave-one-out density, profile likelihood, posterior mean weights |
| Purple | Theory conditions | separation condition, local separation, strong local separation, covariate shift |

Each slide's source is a `::: {.emc-citation}` block, which the template places on a line at the bottom of the slide. The Section 3 opening slide shows the first page of the article with a progressively blurred and lightened lower edge. The closing slide shows the template's `bluecode.jpg` background with a subtle blur toward the bottom. Slides 14, 17, 22, and 25 use the template's light blue boxes; slide 16 uses its teal accent box.

The Bernoulli example of Section 3.1 is a plot drawn by `make_figures.R` from the paper's definitions; the boundaries of the region where the marginally correct model wins are computed numerically (0.25 and 0.675).

`recent-stacking-literature.md` is the annotated comparison of work published after the source article. The conceptual weight diagram and the Section 3.1 plot are generated by `make_figures.R`; the two empirical charts are crops of Figures 3 and 7 from the article.

To rebuild in this folder:

```powershell
Rscript make_figures.R
quarto render bayesian-hierarchical-stacking.qmd
```

The R script needs only base R. The Quarto file uses the Markdown engine, so it does not need `knitr` or `rmarkdown`. The extension requires Quarto 1.5 or newer. Press `S` in the RevealJS presentation for speaker view.

## Local styles and template candidates

`deck-tweaks.css` loads after the EMC stylesheet. Its rules activate only when a slide has the named class in the Quarto heading; the template files remain untouched. The comments in the CSS explain each selector and the two image overlays.

| CSS option | Used on | Template recommendation |
| --- | --- | --- |
| `.emc-equal-boxes` | Slides 14, 17, 22 | Add as an optional two-column layout: equal box heights are useful whenever paired columns contain different amounts of text. |
| `.emc-bottom-blur` | Slide 12 | Add an optional image treatment, ideally with variables for blur strength, start position, and fade color. The white fade still works if a browser lacks `backdrop-filter`. |
| `.emc-closing-bottom-blur` | Slide 27 | Combine with the preceding image treatment as an opt-in variant without the color fade. |
| `.emc-separated-summary` | Slides 14, 17 | Add as a reusable spacing rule for a takeaway immediately below columns. |
| `.emc-forward-equation` | Slide 11 | Keep local: its 25 px equation size and tight spacing were chosen for this slide's two formulas. A general compact-equation option could be added if other decks need it. |

## GitHub Pages

This directory is already a Git repository on `main`, but it has no commits or remote. Create an **empty** GitHub repository first (do not initialize it with a README, license, or `.gitignore`). Replace `USERNAME` and `REPOSITORY` below with its actual owner and name. In PowerShell, run these commands from this directory:

```powershell
git add -- .gitignore bayesian-hierarchical-stacking.qmd deck-tweaks.css README-presentation.md _extensions/stenw/emctemplatereveal assets Bayesianhierarchicalstacking_Page_01.jpg
git diff --cached --stat
git commit -m "Add Quarto stacking presentation"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main

quarto render bayesian-hierarchical-stacking.qmd
quarto publish gh-pages bayesian-hierarchical-stacking.qmd --no-render
```

The explicit `git add` stages the source, local CSS, extension, and referenced images; it leaves the many scratch files and the source PDF out of the commit. Review the staged list before committing. `.gitignore` keeps the locally rendered HTML and support folder on disk for `--no-render` without checking them into `main`. This is **one manual source commit**; Quarto creates and pushes the `gh-pages` deployment branch on the first publish. For a normal project repository, the address is `https://USERNAME.github.io/REPOSITORY/`. If the repository is named `USERNAME.github.io`, select `gh-pages` as the Pages source under GitHub **Settings → Pages** after the first publish. GitHub Pages sites are publicly accessible, including sites backed by eligible private repositories.

For later updates, render locally again, commit and push only changed source files, then run the same `quarto publish gh-pages ... --no-render` command. See the [Quarto GitHub Pages guide](https://quarto.org/docs/publishing/github-pages.html) for the publishing behavior and [GitHub Pages settings](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) for the visibility and source options.
